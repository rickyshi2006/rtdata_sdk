# 可选数值解码模块（实验性，默认关闭）

主 SDK 仍以纯 Python 通用 wheel 分发，不要求安装编译器。新增的独立可选包
`rtdata-numeric-codec` 用于加速无损数值还原，不裁剪字段，不改变行情数值或回调语义。
SDK 0.4.0 保留实验性协商入口；**独立原生可选包不随本次正式发布**，默认行为不变。

## 显式启用

SDK 支持 `RtdataClient(..., realtime_numeric=True)`，高层 `API` 同样支持。
只有服务端同时宣告普通块压缩和数值压缩，且原生模块自检通过，才使用独立的
RBC2 协商；客户端参数本身不能启用服务端能力。

旧服务端、没有可选包或没有显式启用时继续普通 RBLK/V2，不报安装错误。
新协商允许每块择小发送 RBN1、普通 RBLK 或原始 V2；旧 RBC1 客户端不会
收到 RBN1。离线实验 RBLX 不进入实时协议。已协商后的损坏块或能力不匹配会关闭
连接，不静默丢弃并降级。重连重新协商。

`realtime_statistics` 增加 `numeric_negotiated` 与 `numeric_blocks`，分别表示当前
连接是否完成数值能力协商、累计实际接收的数值块数。协商成功不代表每块都用数值压缩。

## 安装与兼容策略

- 原安装命令不变，不增加默认依赖。不支持的平台继续使用原有协议。
- 可选包使用平台专用 wheel，不能将某个平台的动态库复制给其他系统使用。
- 加载时检查 ABI、字段布局和已知样本；每次调用检查浮点运算环境。
- 模块缺失、加载失败或自检不通过时，不声明新编码能力，不自动尝试较慢的实验解码。
- 不接受自定义动态库路径，不从网络下载或运行原生代码。

## 平台验收边界

构建代码面向具有 C11 编译器的 Linux、Windows 和 macOS；CI 矩阵覆盖
Python 3.9、3.12、3.13。矩阵定义不代表已经全部运行通过，跨平台结果须以实际
CI 记录为准。源码包可重新构建平台 wheel；普通用户应使用正式发布且适配平台的成品包。

本机 Linux wheel 的标签为 `linux_x86_64`，没有宣称符合 `manylinux` 或适用于所有
Linux 发行版。可选包不依赖服务端头文件、系统压缩库或 CPython C API，但仍依赖
对应平台的系统 C 运行库。使用既有 SDK 压缩依赖负责解压，再执行原生字节还原。

## 数据与资源约束

输出保留原始字节，包括空值、负零和特殊浮点位模式。每块最多 256 条，原始输出
最多 64 KiB，变换数据最多 128 KiB；遇到无效块，整块拒绝，不交付其中的有效前缀。
每次调用独占输出和 64 KiB 原生栈缓冲；不依赖上一块行情或跨品种状态。

原生计算要求默认浮点舍入模式，环境不符合时明确拒绝，不修改调用方设置。
无新增凑批等待，但编码和还原仍消耗 CPU。吞吐、延迟和带宽收益须以同负载端到端
对照为准，不能把压缩比例直接当作节点容量或千客户端验收结果。
